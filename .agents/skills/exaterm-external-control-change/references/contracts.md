## Review Decisions

- Compare observable behavior against the supplied base and intended change. A requested contract change is not itself a defect; identify unsynchronized consumers, unintended incompatibility, or incomplete migration.
- Do not demand CLI/MCP feature parity. For example, CLI log-start destination options and the MCP session-only schema can intentionally differ. Verify the actual affected adapter's contract.
- Treat changed shared-service behavior as a possible contract change even when adapter files are untouched. Follow it through serialization and consumers before concluding that documentation is unaffected.
- A fake that bypasses permission checks, finalization, or result construction cannot establish the production service's behavior. Prefer regression evidence that exercises those paths and their public boundary.
- Cite a concrete triggering condition and consequence for each defect. Keep uncertain hypotheses and unavailable runtime evidence separate from confirmed findings; static inspection cannot prove GUI or hardware success.
